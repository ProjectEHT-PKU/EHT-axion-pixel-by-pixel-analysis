# 数据布局

## 用途

本页列出每个脚本写出的目录和文件，以及数组形状、轴顺序和单位，使每个产品都能在不运行代码的情况下
被找到和读取。大写名称（`RUN_ROOT`、`TEMPLATES`、…）是在命令行中给出的输出根目录。除非另有说明，
每个标有阶段名的目录都含有 `manifest.json`（[来源记录](provenance.md)）。

## 输入

下列产品由后续脚本读取，方式见 [RAPTOR 模拟](raptor-simulation.md)、[EHT 成像](eht-imaging.md)和
[分析](analysis.md)。

## 输出

### RAPTOR 模拟

```text
RUN_ROOT/
  config.yaml                    copy of the experiment file of this run
  requests/<uuid>.json           one record per raptor_build / raptor_generate call
  build/                         stage raptor:build
    RAPTOR                       executable
    source/                      tracked RAPTOR source bytes at raptor.source.commit
    definitions.h, model_*.h, grid_mks.in, ...   files generated by setup.sh
    compile.log, compiler-flags.txt, macros.txt, receipt.json
  jobs/<task id>/                stage raptor:job
    task.json, model.in, grid_mks.in
    output/img_data_<slot>.h5    I, Q, U, V (Jy/sr), tau, tauF, alpha, beta (r_g)
    output/spectrum_<slot>_<inclination>.dat   frequency (Hz), I, Q, U, V (Jy)
    output.json, success.json, stdout.log, stderr.log
  attempts/<task id>/attempt-*/  input.json, stdout.log, stderr.log, result.json, work/ (failures)
  data/raptor/
    res-100/alpha-<α>/           stage raptor:delivery, one per alpha
      stokes.npy                 float64 (141, 17, 100, 100, 4)
      generated.json, sources.json, convert.json
    res-400/background/t<A>-t<B>/   stage raptor:delivery, one per shard
      stokes-t<A>-t<B>.npy       float64 (T <= 10, 1, 400, 400, 4)
      generated.json, sources.json, convert.json
```

`raptor_merge.py` 写出与上面相同的 `OUTPUT/data/raptor/...`，以及 `OUTPUT/inventory/index.json`
（阶段 `raptor:merge`）。

交付的数据立方：轴依次为（时间、状态、x、y、Stokes）；Stokes 顺序为 I、Q、U、V，单位 Jy/sr；x 和 y
是相机轴。状态 0 为无轴子；状态 $k+1$ 的轴子相位为 $k\pi/8$。`generated.json` 存放光线追踪配置、
`alpha`（背景为 null）、`resolution`、`snapshot_labels`、`times_tg`（尾部时间）、`state_count`、
`omega` 以及轴和单位的说明。`sources.json` 把每个任务标识符映射到其作业根目录。

D 项 JSON 文件把台站映射到 `[[Re D_R, Im D_R], [Re D_L, Im D_L]]`（小数，不是百分数）。FITS 图像有
四个 HDU：I、Q、U、V，采用原生 `RA---SIN`/`DEC--SIN` 坐标轴；东向偏移随 x 下标减小，北向偏移随 y
下标增大。`<day>-<draw>` 使用四位抽样序号，例如 `95-0042`。

`eht_summarize.py` 直接读取上面的 `MC/` 根目录。

  table-limits.tex, table-chi2.tex   complete tabular environments

分析中的下标约定：

- 2D `selected_indices` 是模板网格 $[x, y]$（即转置后的 EHT 图）上的展平下标 $64\,x + y$；
  `coordinates` 是以 µas 为单位的（东，北）偏移。
- 1D `selected_indices` 是以北偏东度数表示的扇区角。
- `observations-*.npz` 中带天轴的数组按 95、96、100、101 排序；日对数组按（96−95, 101−100）排序。
- 在 `limits.csv` 中，`data` 列的取值为 `observed` 或 `zero-data`。

## 运行方法

这些产品由 [RAPTOR 模拟](raptor-simulation.md)、[EHT 成像](eht-imaging.md)和[分析](analysis.md)
中的命令写出。`pixi run verify DIR` 检查一个阶段目录。

## 细节

### 默认布局

每个根目录要么在命令行中给出（对 RAPTOR 和 EHT 成像的输入，也可以写在 `.env` / `.env.raptor`
中），要么由同一个数据根目录派生；代码中不假定任何机器位置。一次实验的产品保存在该数据根目录之下，
每个部分一个目录：

```text
<data root>/
  raptor/
    plan.json                    frozen task plan (raptor_generate.py --plan --plan-output)
    runs/<name>/                 run roots of raptor_generate.py (build/, jobs/, attempts/,
                                 config.yaml, requests/); one per host or build; default runs/main
    delivered/                   raptor_merge.py output root: data/raptor/res-*/..., inventory/
  eht/
    intensity/day-<day>/         eht_reconstruct.py --stage I
    fiducial/day-<day>/          eht_reconstruct.py --stage fiducial
    refine/day-<day>/            eht_refine.py
    bundle/                      eht_export_bundle.py
    sample/                      eht_sample.py
    ensemble/                    eht_summarize.py
  analysis/
    templates/                   analysis_templates.py (--raptor-input-root raptor/delivered/data)
    limits/                      analysis_limits.py
    check-grid/                  analysis_check_grid.py with a denser phase and coupling grid
    check-prior/                 analysis_check_grid.py with a wider coupling range
    check-covariance/            analysis_check_covariance.py
    summary/                     analysis_summarize.py
    paper/                       analysis_paper.py
```

`M87_AXION_DATA_ROOT`（已导出的环境变量或写在 `.env` 中）或 `--data-root` 指定数据根目录；此后每个
脚本都按这一布局取得默认的输入和输出根目录，显式给出的 `--...-root` 选项覆盖默认值。默认的 RAPTOR
运行根目录是 `raptor/runs/main`（可由 `--run-root` 或 `EHT_RAPTOR_RUN_ROOT` 覆盖）；`raptor_merge.py`
默认合并 `raptor/runs/` 中的每个目录；`analysis_check_grid.py` 需要 `--check grid` 或 `--check prior`
来选择默认输出根目录。产生结果的脚本仍然拒绝已有的输出根目录，因此一个默认输出根目录只能写入一次。

按这一布局，用于得出结果的 RAPTOR 运行有两个运行根目录：`runs/main`（18 234 个作业）和
`runs/background`（96 个无轴子 400 像素作业，标签 2050–3000，用第二次编译生成）；`raptor_merge.py`
把二者一起交付到 `delivered/`。
