# 数据布局与溯源机制

[← 返回文档索引](index.md)

科学数据数组与插图从不存入 Git 代码仓库。所有流水线脚本都从单一数据根目录（`EHT_DATA_ROOT` 或 `--data-root`）派生默认的产物目录，并从单一只读输入根目录（`EHT_INPUT_ROOT` 或 `--input-root`）派生外部输入路径，并以原子方式写入由阶段清单（manifest，`manifest.json`）或显式批次/打包回执描述的目录。

## 默认目录布局

在 `.env` 或 shell 中设置 `EHT_DATA_ROOT`，或通过命令行传入 `--data-root PATH`，即可将整次实验组织在同一个目录之下（见 `eht_axion/environment.py` 中的 `LAYOUT`）：

```text
<data root>/
  raptor/                        raptor/build.py, raptor/generate.py
    plan.json                    task plan, written by the first raptor/generate.py run
    build/                       raptor/build.py
    jobs/                        raptor/generate.py: one directory per task
    images/                      raptor/generate.py: Stokes image cubes
  eht/
    intensity/day-<day>/         eht/reconstruct.py --stage I
    fiducial/day-<day>/          eht/reconstruct.py --stage fiducial
    refine/day-<day>/            eht/refine.py
    sample/                      eht/sample.py
    ensemble/                    eht/summarize.py
  analysis/
    expected-signal/             analysis/expected_signal.py (reads raptor/images)
    limits/                      analysis/limits.py
    summary/                     analysis/summarize.py
    paper/                       analysis/paper.py
```

显式传入 `--...-root` 选项会覆盖默认路径。

## 输入目录布局

外部输入只读、从不写入。在 `.env` 或 shell 中设置 `EHT_INPUT_ROOT`，或通过命令行传入 `--input-root PATH`，即可在同一目录下定位全部外部输入（见 `eht_axion/environment.py` 中的 `INPUT_LAYOUT`）；第三个根目录 `EHT_RAPTOR_SOURCE_ROOT` 则是 `RAPTOR` 的 Git 工作副本：

```text
<input root>/
  grmhd/                         data001600.dat ... data003000.dat (BHAC snapshots; --fluid-root)
  radial/
    result_a=0.9375_l1m1.txt     radial table "low" (spin 0.9375; --radial-low)
    result_a=0.99_l1m1.txt       radial table "high" (spin 0.99; --radial-high)
  eht/                           directory of the uvfits files (--uvfits-dir)
    SR2_M87_2017_<day>_lo_hops_zbl-dtcal+selfcal.uvfits   eht_imaging.inputs (name, SHA-256)
    eht-imaging_pipeline.py      official EHT imaging script (--official-script)
```

径向表文件名分别对应 `raptor.radial_tables` 的 `low` 与 `high`；四个 `uvfits` 文件名及其 SHA-256 摘要即 `configs/experiment.yaml` 中的 `eht_imaging.inputs`。括号中所示的显式选项可覆盖单个条目。`scripts/analysis/paper.py` 按 `raptor/plan.json` 中记录的 SHA-256 核对径向表，并从 `RAPTOR` 工作副本读取 `src/axion.c`，该工作副本必须洁净地处于 `raptor.source.commit`。

## 各阶段文件与数组规范

除非另有说明，下列标有阶段名（`stage`）的每个目录均包含一份 `manifest.json`。

### `RAPTOR` 模拟

```text
raptor/
  plan.json                      task plan: configuration, snapshots and radial tables with SHA-256, tasks
  build/                         stage raptor:build
    RAPTOR                       compiled executable (from the clean checkout at raptor.source.commit)
    definitions.h, model_*.h, grid_mks.in, ...   files generated by setup.sh
    compile.log, compiler-flags.txt, macros.txt, receipt.json
  jobs/<task id>/                stage raptor:job (res-<n>/alpha-<α>/t<label>/phase-<k>, res-<n>/baseline/t<label>)
    model.in                     RAPTOR parameters of the task
    output/img_data_<slot>.h5    {I,Q,U,V,tau,tauF}<freq:e>, alpha, beta; shape ((N/10)^2, 100)
    output/spectrum_<slot>_<inclination>.dat   frequency (Hz), I, Q, U, V (Jy)
    stdout.log, stderr.log
  attempts/<task id>/attempt-*/  input.json, stdout.log, stderr.log, result.json (+ work/ on failure)
  images/
    res-100/alpha-<α>/           stage raptor:images (8 directories, alpha-0.10 .. alpha-0.44)
      stokes.npy                 float64 (141, 17, 100, 100, 4) in Jy/sr
      generated.json
    res-400/background/          stage raptor:images
      stokes.npy                 float64 (141, 1, 400, 400, 4) in Jy/sr
      generated.json
```

图像数据立方 `stokes.npy` 的坐标轴顺序为 `(time, state, x, y, Stokes)`，斯托克斯（Stokes）通道顺序为 `[I, Q, U, V]`，单位为 $\mathrm{Jy\,sr^{-1}}$；状态 `0` 为无轴子基线，状态 `k+1` 对应轴子相位 $k\pi/8$。

### EHT 成像

```text
I<day>/                          stage eht:i
  official-I-120-direct.py       the official script as executed (two adapted strings)
  final-fixedI.fits              fixed total-intensity image (64 x 64, 120 uas)
  clean-gaincal-pol.uvfits       native circular visibilities with shared R=L gains applied
  shared-gains.npz, polarization-input.json
PD<day>/                         stage eht:fiducial
  steps.json, termination.json
  rounds.npz                     rounds 1..50: sites; raw_qu, blurred_qu (50, 2, 64, 64) [Q, U];
                                 dterms (50, sites, hand R/L, real/imag)
  final-raw-IQU.fits, final-blurred-IQU.fits, final-dterms.json
D<day>/                          stage eht:refine
  steps.json, D-optimizer-records.json, termination.json
  rounds.npz                     rounds 1..100, as for eht:fiducial
  final-raw-IQU.fits, final-blurred-IQU.fits, final-dterms.json   (call 101: P aligned with the last D)
MC/                              signed by batch/task/finish receipts (no manifest.json)
  .controller.lock, batch.json, all-draws.json, finish.json (state.json while running)
  attempts/<day>-<draw>/attempt-<NNNN>/
    job.log, progress.json, certificate.json, taskreceipt.json
    best-raw-IQU.fits, best-blurred-IQU.fits
ENSEMBLE/                        stage eht:ensemble
  axes.npz                       east_uas (64), north_uas (64)
  report.json
  stokes.npy                     float64 (4, 1000, 64, 64, 4): [day, draw, y, x, IQUV]
  global.npz                     values (4, 1000, 6); days; columns: total_I, m_net, m_resolved,
                                 evpa_rad, beta2_real, beta2_imag
```

仪器偏振泄漏（D 项，D-term）JSON 文件将台站代码映射为 `[[Re D_R, Im D_R], [Re D_L, Im D_L]]`（无量纲复数泄漏比例，非百分数）。偏振 EHT FITS 文件（`*-IQU.fits`）均包含四个二维扩展单元（HDU：`I`、`Q`、`U`、`V`，其中 `V = 0`），采用原生 `RA---SIN` / `DEC--SIN` 投影轴（东向偏移随 `x` 增大而减小，北向偏移随 `y` 增大而增大）。抽样编号 `<day>-<draw>` 使用四位补零序号（`95-0000` … `101-0999`）。

### 分析

```text
EXPECTED_SIGNAL/                 stage analysis:expected-signal (no intermediate products)
  expected.npz                   <1d|2d>/alphas (8); <1d|2d>/amplitude_mean, amplitude_std, phase_mean,
                                 phase_std (rad per raptor.response.reference_norm), amplitude_count,
                                 phase_count: (8, 360) sectors or (8, 64, 64) pixels
  background.npy                 float64 (141, 1, 64, 64, 4): axion-off images on the sky grid
LIMITS/                          stage analysis:limits
  report.json                    identity, results table, notes; sections observations/<1d|2d>,
                                 background/<1d|2d>, cases/<data>-<mode>-<dim> without their arrays
  results.npz                    every array of the sections as "<section>/<name>/<field>", e.g.
                                 observations/1d/pair_covariances, background/2d/differences,
                                 cases/observed-cor-1d/log_likelihood
  limits.csv                     columns: data, mode, dimension, alpha, log10_c95, c95
  observed-vs-zero-data.png
SUMMARY/                         stage analysis:summary
  limits.csv, fit-chi2.csv
  limits.png, fits-alpha-<α>.png (8 files), report.json, RESULTS.md
PAPER/                           stage analysis:paper
  figures/<name>.pdf             radial_function, two_photon, signal_maps, template_maps, background,
                                 observational_uncertainty, data_vs_model, limits
  numbers.tex, numbers.json      quoted paper macros, unrounded values, and sources
  table-limits.tex, table-chi2.tex
```

**分析产品中的下标与排序约定：**
- 2D `selected_indices` 为预期信号网格 `[x, y]`（`x = -East`，`y = +North`）上的行优先展平下标 $64\,x + y$；`coordinates` 保存 `(east_uas, north_uas)`。
- 1D `selected_indices` 为以北偏东整度数表示的扇区中心角（`0`–`359`）。
- 观测日轴固定按 `(95, 96, 100, 101)` 排列；日对轴固定按 `(96 - 95, 101 - 100)` 排列。

## 溯源机制与阶段清单（`eht_axion/provenance.py`）

### 原子化阶段创建与输出根目录规则

每个基于清单的数据溯源（provenance）阶段都由上下文管理器 `stage_directory(destination, stage, config, input_paths)` 创建：
- 拒绝经由目录符号链接到达的目标路径，并拒绝与 `source_closure(input_paths)` 中任何输入文件重叠的目标路径。
- 以 `O_CREAT | O_EXCL` 独占方式创建 `<destination>.lock`（并发写入者会立即报错退出，而不是阻塞等待）。
- **洁净工作树规则（`code_identity`）**：若 `git status --porcelain --untracked-files=no` 检测到受版本控制文件存在未提交改动，代码拒绝创建任何新阶段。由于工作树洁净，记录完整提交号 `HEAD`（`implementation.git_commit`）即可唯一锁定全部脚本、`eht_axion/` 模块、`configs/experiment.yaml`、`pixi.toml` 与 `pixi.lock`，因此仓库自身文件不列入 `inputs`。
- 阶段主体先写入同级临时目录 `<destination>.building-*`；完成后列出全部常规输出文件（禁止符号链接，禁止空阶段），最后写入 `manifest.json`，再将临时目录原子重命名为 `<destination>`。若中途抛出异常，自动清理临时目录与锁文件。
- **不可变输出与断点续跑**：产生结果的脚本（`reconstruct.py`、`refine.py`、`eht/summarize.py` 以及全部 `scripts/analysis/*.py`）一律拒绝已存在的 `--output-root`。设计上支持续跑的步骤（`raptor/build.py`、`raptor/generate.py`）在目标阶段已存在时，仅当其已完成且记录的 `(stage, config, inputs)` 完全一致时才复用缓存；该比较有意忽略 `git_commit`，使长时运行的 `RAPTOR` 批次可在不改变光线追踪任务的提交之后继续续跑。

### `manifest.json` 结构与阶段标识符

| 字段 | 内容说明 |
|---|---|
| `stage` | 固定的阶段标识符 `<part>:<step>`（见下表） |
| `config` | 决定本阶段的 JSON 序列化参数字典 |
| `inputs` | 每个外部或上游消费文件的解析后路径 |
| `implementation` | `{"git_commit": "<40-hex HEAD>"}` |
| `runtime` | Python 版本与实现、操作系统/硬件架构，以及 `numpy`、`scipy`、`h5py`、`matplotlib`、`PyYAML` 的版本号 |
| `complete` | `true`；`stage` 为非空字符串且 `complete: true` 的 `manifest.json` 即标识一个已完成阶段 |
| `outputs` | 每个输出文件的 `{path}` 列表（对 `.npy` 额外记录 `shape`/`dtype`，对 `.npz` 记录各命名数组的形状和数据类型；均通过 `allow_pickle=False` 的只读内存映射 `mmap` 读取） |
| `elapsed_seconds` | 阶段主体的墙钟运行秒数 |

| 阶段标识符 | 写出脚本 |
|---|---|
| `raptor:build` | `scripts/raptor/build.py` |
| `raptor:job` | `scripts/raptor/generate.py` |
| `raptor:images` | `scripts/raptor/generate.py` |
| `eht:i`、`eht:fiducial` | `scripts/eht/reconstruct.py` |
| `eht:refine` | `scripts/eht/refine.py` |
| `eht:ensemble` | `scripts/eht/summarize.py` |
| `analysis:expected-signal` | `scripts/analysis/expected_signal.py` |
| `analysis:limits` | `scripts/analysis/limits.py` |
| `analysis:summary` | `scripts/analysis/summarize.py` |
| `analysis:paper` | `scripts/analysis/paper.py` |

阶段清单之外的辅助 JSON 记录用 `schema`（或 `layout`）字符串标明记录类型：`raptor-generated`、`eht-sample-batch`、`eht-sample-task`、`eht-sample-finish`、`eht-ensemble`、`analysis-limits`、`analysis-summary`、`analysis-paper` 和 `analysis-paper-numbers`。

### 非清单类回执记录

EHT 流水线中有一个步骤使用专门设计的回执记录来管理只读跨天容器或可续跑蒙特卡罗（Monte Carlo）批次，而不写 `manifest.json`：
- **`MC/batch.json`、`taskreceipt.json` 与 `finish.json`**（`scripts/eht/sample.py`）：`batch.json` 记录批次计划（四天的输入文件、科学参数、`git_commit`、依赖包版本及线程数），续跑要求计划相同。每次尝试写出 `taskreceipt.json`（任务、状态、输出文件名）；仅当全部 $4000$ 次抽样获得证书后写出 `finish.json`，并由 `scripts/eht/summarize.py` 在生成 `eht:ensemble` 前逐一检查所有回执与证书。
