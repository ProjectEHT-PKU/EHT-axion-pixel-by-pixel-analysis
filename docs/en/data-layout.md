# Data Layout and Provenance

[← Documentation index](index.md)

Scientific arrays and figures are never stored inside the git repository. Every pipeline script derives its default product directories from a single data root (`EHT_DATA_ROOT` or `--data-root`) and its external inputs from a single read-only input root (`EHT_INPUT_ROOT` or `--input-root`), and writes results atomically into stage directories described by `manifest.json` (or explicit batch/bundle receipts).

## Default layout

Setting `EHT_DATA_ROOT` (in `.env` or the shell) or passing `--data-root PATH` organizes an entire experiment under one directory (`eht_axion/environment.py`, `LAYOUT`):

```text
<data root>/
  raptor/                        raptor/build.py, raptor/generate.py
    plan.json                    task plan, written by the first raptor/generate.py run
    build/                       raptor/build.py
    jobs/                        raptor/generate.py: one directory per task
    images/                      raptor/generate.py: Stokes image cubes
  eht/
    intensity/day-<day>/         eht/reconstruct.py --stage I
    fiducial/day-<day>/          eht/reconstruct.py --stage fiducial
    refine/day-<day>/            eht/refine.py
    sample/                      eht/sample.py
    ensemble/                    eht/summarize.py
  analysis/
    expected-signal/             analysis/expected_signal.py (reads raptor/images)
    constraints/                 analysis/constraints.py
    paper/                       analysis/paper.py
```

Explicit `--...-root` flags override any default path.

## Input layout

External inputs are only read, never written. Setting `EHT_INPUT_ROOT` (in `.env` or the shell) or passing `--input-root PATH` locates all of them under one directory (`eht_axion/environment.py`, `INPUT_LAYOUT`); the third root, `EHT_RAPTOR_SOURCE_ROOT`, is the `RAPTOR` git checkout:

```text
<input root>/
  grmhd/                         data001600.dat ... data003000.dat (BHAC snapshots; --fluid-root)
  radial/
    result_a=0.9375_l1m1.txt     radial table "low" (spin 0.9375; --radial-low)
    result_a=0.99_l1m1.txt       radial table "high" (spin 0.99; --radial-high)
  eht/                           directory of the uvfits files (--uvfits-dir)
    SR2_M87_2017_<day>_lo_hops_zbl-dtcal+selfcal.uvfits   eht_imaging.inputs (name, SHA-256)
    eht-imaging_pipeline.py      official EHT imaging script (--official-script)
```

The radial-table file names belong to the `raptor.radial_tables` ids `low` and `high`; the four `uvfits` names and SHA-256 digests are `eht_imaging.inputs` of `configs/experiment.yaml`. Explicit options (shown in parentheses) override single entries. `scripts/analysis/paper.py` checks the radial tables against the SHA-256 recorded in `raptor/plan.json` and reads `src/axion.c` from the `RAPTOR` checkout, which must be clean at `raptor.source.commit`.

## Stage files and array specifications

Unless noted otherwise, every directory tagged with a `stage` identifier contains a `manifest.json`.

### `RAPTOR` simulation

```text
raptor/
  plan.json                      task plan: configuration, snapshots and radial tables with SHA-256, tasks
  build/                         stage raptor:build
    RAPTOR                       compiled executable (from the clean checkout at raptor.source.commit)
    definitions.h, model_*.h, grid_mks.in, ...   files generated by setup.sh
    compile.log, compiler-flags.txt, macros.txt, receipt.json
  jobs/<task id>/                stage raptor:job (res-<n>/alpha-<α>/t<label>/phase-<k>, res-<n>/baseline/t<label>)
    model.in                     RAPTOR parameters of the task
    output/img_data_<slot>.h5    {I,Q,U,V,tau,tauF}<freq:e>, alpha, beta; shape ((N/10)^2, 100)
    output/spectrum_<slot>_<inclination>.dat   frequency (Hz), I, Q, U, V (Jy)
    stdout.log, stderr.log
  attempts/<task id>/attempt-*/  input.json, stdout.log, stderr.log, result.json (+ work/ on failure)
  images/
    res-100/alpha-<α>/           stage raptor:images (8 directories, alpha-0.10 .. alpha-0.44)
      stokes.npy                 float64 (141, 17, 100, 100, 4) in Jy/sr
      generated.json
    res-400/background/          stage raptor:images
      stokes.npy                 float64 (141, 1, 400, 400, 4) in Jy/sr
      generated.json
```

Image-cube `stokes.npy` axes are `(time, state, x, y, Stokes)` with channels `[I, Q, U, V]` in $\mathrm{Jy\,sr^{-1}}$; state `0` is axion-off and state `k+1` has axion phase $k\pi/8$.

### EHT imaging

```text
I<day>/                          stage eht:i
  official-I-120-direct.py       the official script as executed (two adapted strings)
  final-fixedI.fits              fixed total-intensity image (64 x 64, 120 uas)
  clean-gaincal-pol.uvfits       native circular visibilities with shared R=L gains applied
  shared-gains.npz, polarization-input.json
PD<day>/                         stage eht:fiducial
  steps.json, termination.json
  rounds.npz                     rounds 1..50: sites; raw_qu, blurred_qu (50, 2, 64, 64) [Q, U];
                                 dterms (50, sites, hand R/L, real/imag)
  final-raw-IQU.fits, final-blurred-IQU.fits, final-dterms.json
D<day>/                          stage eht:refine
  steps.json, D-optimizer-records.json, termination.json
  rounds.npz                     rounds 1..100, as for eht:fiducial
  final-raw-IQU.fits, final-blurred-IQU.fits, final-dterms.json   (call 101: P aligned with the last D)
MC/                              signed by batch/task/finish receipts (no manifest.json)
  .controller.lock, batch.json, all-draws.json, finish.json (state.json while running)
  attempts/<day>-<draw>/attempt-<NNNN>/
    job.log, progress.json, certificate.json, taskreceipt.json
    best-raw-IQU.fits, best-blurred-IQU.fits
ENSEMBLE/                        stage eht:ensemble
  axes.npz                       east_uas (64), north_uas (64)
  report.json
  stokes.npy                     float64 (4, 1000, 64, 64, 4): [day, draw, y, x, IQUV]
  global.npz                     values (4, 1000, 6); days; columns: total_I, m_net, m_resolved,
                                 evpa_rad, beta2_real, beta2_imag
```

D-term JSON files map station codes to `[[Re D_R, Im D_R], [Re D_L, Im D_L]]` (fractional complex leakage, not percent). Polarimetric EHT FITS files (`*-IQU.fits`) store four 2D HDUs (`I`, `Q`, `U`, `V`, with `V = 0`) on native `RA---SIN` / `DEC--SIN` axes (east offset decreases with `x`, north offset increases with `y`). Draw IDs `<day>-<draw>` use four-digit zero-padded indices (`95-0000` … `101-0999`).

### Analysis

```text
EXPECTED_SIGNAL/                 stage analysis:expected-signal (no intermediate products)
  expected.npz                   <1d|2d>/alphas (8); <1d|2d>/amplitude_mean, amplitude_std, phase_mean,
                                 phase_std (rad per raptor.response.reference_norm), amplitude_count,
                                 phase_count: (8, 360) sectors or (8, 64, 64) pixels
  background.npy                 float64 (141, 1, 64, 64, 4): axion-off images on the sky grid
CONSTRAINTS/                     stage analysis:constraints
  report.json                    identity, results table, notes; sections observations/<1d|2d>,
                                 background/<1d|2d>, cases/<data>-<mode>-<dim> without their arrays
  results.npz                    every array of the sections as "<section>/<name>/<field>", e.g.
                                 observations/1d/pair_covariances, background/2d/differences,
                                 cases/observed-cor-1d/log_likelihood
  constraints.csv                columns: data, mode, dimension, alpha, log10_c95, c95
PAPER/                           stage analysis:paper
  figures/<name>.pdf             radial_function, two_photon, signal_maps, template_maps, background,
                                 observational_uncertainty, data_vs_model, limits
  numbers.tex, numbers.json      quoted paper macros, unrounded values, and sources
  table-limits.tex, table-chi2.tex
```

**Indexing conventions in analysis products:**
- 2D `selected_indices` are flat row-major indices $64\,x + y$ into the expected-signal grid `[x, y]` (`x = -East`, `y = +North`); `coordinates` holds `(east_uas, north_uas)`.
- 1D `selected_indices` are integer sector centres in degrees east of north (`0`–`359`).
- Day axes follow `(95, 96, 100, 101)`; pair axes follow `(96 - 95, 101 - 100)`.

## Provenance and stage manifests (`eht_axion/provenance.py`)

### Atomic stage creation and output-root policy

`stage_directory(destination, stage, config, input_paths)` wraps every manifest-backed stage:
- Rejects destinations reached via directory symlinks or overlapping any file in `source_closure(input_paths)`.
- Acquires `<destination>.lock` with `O_CREAT | O_EXCL` (concurrent writers fail immediately rather than blocking).
- **Clean-tree rule (`code_identity`)**: refuses to create a new stage if `git status --porcelain --untracked-files=no` reports uncommitted changes to any tracked repository file. Because the working tree is clean, recording `HEAD` (`implementation.git_commit`) uniquely pins every script, `eht_axion/` module, `configs/experiment.yaml`, `pixi.toml`, and `pixi.lock`; repository files are therefore never listed in `inputs`.
- Writes outputs into a sibling temporary directory `<destination>.building-*`, lists all produced regular files (no symlinks, non-empty), writes `manifest.json` last, and atomically renames the directory to `<destination>`. On exception, the temporary directory and lock are removed.
- **Immutability vs. resume**: result scripts (`reconstruct.py`, `refine.py`, `eht/summarize.py`, and all `scripts/analysis/*.py`) refuse an existing `--output-root`. Resumable steps (`raptor/build.py`, `raptor/generate.py`) reuse an existing stage directory only if it is complete and records identical `(stage, config, inputs)`; `git_commit` is omitted from that cache comparison so a long `RAPTOR` run can resume across commits that do not alter its tasks.

### `manifest.json` fields and stage identifiers

| Field | Contents |
|---|---|
| `stage` | Fixed stage identifier `<part>:<step>` (table below) |
| `config` | JSON-serialized parameter dictionary governing this stage |
| `inputs` | Resolved paths of every consumed external or upstream file |
| `implementation` | `{"git_commit": "<40-hex HEAD>"}` |
| `runtime` | Python version/implementation, OS/machine, and versions of `numpy`, `scipy`, `h5py`, `matplotlib`, `PyYAML` |
| `complete` | `true`; a `manifest.json` with a non-empty string `stage` and `complete: true` is what identifies a completed stage |
| `outputs` | List of `{path}` (plus `shape`/`dtype` for `.npy` and per-array shapes/dtypes for `.npz`, inspected via `mmap` with `allow_pickle=False`) |
| `elapsed_seconds` | Wall-clock execution time of the stage body |

| Stage name | Producer script |
|---|---|
| `raptor:build` | `scripts/raptor/build.py` |
| `raptor:job` | `scripts/raptor/generate.py` |
| `raptor:images` | `scripts/raptor/generate.py` |
| `eht:i`, `eht:fiducial` | `scripts/eht/reconstruct.py` |
| `eht:refine` | `scripts/eht/refine.py` |
| `eht:ensemble` | `scripts/eht/summarize.py` |
| `analysis:expected-signal` | `scripts/analysis/expected_signal.py` |
| `analysis:constraints` | `scripts/analysis/constraints.py` |
| `analysis:paper` | `scripts/analysis/paper.py` |

Auxiliary JSON records name their record type in a `schema` (or `layout`) string: `raptor-generated`, `eht-sample-batch`, `eht-sample-task`, `eht-sample-finish`, `eht-ensemble`, `analysis-constraints`, `analysis-paper`, and `analysis-paper-numbers`.

### Non-manifest receipts

One EHT step manages resumable or read-only multi-day containers with dedicated receipts instead of `manifest.json`:
- **`MC/batch.json`, `taskreceipt.json`, and `finish.json`** (`scripts/eht/sample.py`): `batch.json` stores the batch plan (the input files of the four days, science settings, `git_commit`, package versions, and thread count); a resume requires the same plan. Each attempt writes `taskreceipt.json` (task, status, output file names); `finish.json` is written only when all $4000$ draws are certified, and `scripts/eht/summarize.py` checks every receipt and certificate before creating `eht:ensemble`.
